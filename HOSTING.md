# Хостинг «Генератора AR-меток» — бесплатно, надолго, быстро

Цель: сайт живёт по постоянному адресу с HTTPS, метки синхронизируются между
устройствами через бесплатную облачную БД. Всё на бесплатных тарифах:
**Vercel** (хостинг Next.js) + **Supabase** (PostgreSQL). Аккаунты нужны ваши —
код, схема БД и переменные окружения в проекте уже готовы.

## Архитектура (что куда заливается)

- **Сайт** — Next.js. Вся генерация меток происходит в браузере (canvas):
  серверной логики для меток нет, поэтому сайт быстрый и дешёвый в хостинге.
- **Облако** — одна таблица `markers`, в ней только названия меток: узор
  детерминированно восстанавливается из названия на любом устройстве.
- Клиент читает и пишет облако напрямую (PostgREST REST API, анонимный
  ключ) — дополнительный сервер не нужен, записи охраняет RLS.
- Без ключей облака приложение работает в локальном режиме (история в
  браузере, чип «Локально» в шапке истории).

## Шаг 1. Supabase — облачная БД (около 5 минут)

1. `supabase.com` → **Start your project** → регистрация (удобно через GitHub).
2. **New project** → имя, например `ar-markers` → регион **Frankfurt (eu-central-1)**
   (ближе к Беларуси/России — быстрее отвечает) → **Create**.
3. Подождать статус проекта **Ready** (1–2 минуты).
4. Левое меню → **SQL Editor** → **New query** → вставить целиком содержимое
   файла `scripts/supabase-schema.sql` → **Run** → ответ «Success».
5. **Project Settings → API** — оттуда понадобятся два значения:
   - **Project URL** — вида `https://xxxxxxx.supabase.co`
   - **anon public** — длинный ключ (публичный по дизайну, это не секрет).

## Шаг 2. GitHub — код сайта (около 5 минут)

1. `github.com` → **New repository** → имя, например `ar-markers` → Create.
2. В папке проекта:

```bash
git add -A
git commit -m "AR-метки: генератор, PWA, PDF, облако"
git remote add origin https://github.com/ВАШ_ЛОГИН/ar-markers.git
git branch -M main
git push -u origin main
```

`.env` в репозиторий не попадает (в `.gitignore`) — ключи задаются
только на Vercel. Локальные артефакты (скриншоты, снапшоты сборки, базы)
тоже отфильтрованы.

## Шаг 3. Vercel — хостинг (около 5 минут)

1. `vercel.com` → **Sign up with GitHub**.
2. **Add New → Project** → **Import** репозиторий `ar-markers`.
3. Перед деплоем — **Environment Variables**, добавить обе:

| Имя | Значение |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL из шага 1 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public ключ из шага 1 |

4. **Deploy**. Через 1–2 минуты сайт живёт на адресе вида
   `ar-markers-xxx.vercel.app` — HTTPS уже включён.
5. На телефоне: открыть адрес → меню браузера → «Добавить на главный экран» —
   приложение установится как PWA и будет работать даже офлайн (service
   worker кеширует оболочку; для установки и офлайна обязателен HTTPS —
   на Vercel он есть из коробки).

## Шаг 4. Проверка синхронизации

Откройте сайт на компьютере, введите название метки и скачайте PNG. Затем
откройте тот же адрес на телефоне (или в другом браузере): в истории
появится эта метка с бейджем «Облако», а чип в шапке истории покажет
«Синхронизировано». Ссылка «Поделиться» тоже работает между устройствами.

## Обновления сайта

Любой `git push` в ветку `main` → Vercel автоматически пересобирает и
публикует новую версию (~2 минуты). Ничего нажимать не нужно.

## Лимиты бесплатных тарифов (честно)

- **Vercel Hobby**: неограниченные деплои, ~100 ГБ трафика в месяц — для
  этого приложения запас огромный. Тариф некоммерческий (для личных
  проектов — идеально).
- **Supabase Free**: 500 МБ БД (одна строка метки — доли килобайта, хватит
  на десятки тысяч меток), ~2 ГБ трафика в месяц. После ~7 дней без
  запросов проект «засыпает»: метки НЕ пропадают, просто первый запрос
  после паузы разбудит проект за ~30 секунд.
- Если облако недоступно — приложение продолжает полноценно работать
  локально, чип покажет «Облако недоступно», клик по нему — повторная
  попытка.

## Свой домен (по желанию)

Адрес `xxx.vercel.app` бесплатен и постоянен. Свой домен (например,
`armarki.ru`) покупается у регистратора (~200–400 руб/год) и подключается
в Vercel → Project → Settings → Domains → Add — DNS-записи Vercel
подскажет и проверит сам, HTTPS выпускается автоматически.

## Альтернативы Vercel (если вдруг понадобится)

- **Netlify** — похожий бесплатный тариф, импорт из GitHub тоже в пару
  кликов.
- **Cloudflare Pages** — щедрый бесплатный трафик, но сборка Next.js
  требует больше настройки.

## Локальная разработка

```bash
bun install
bun run dev                 # http://localhost:3000, облако выключено
```

Облачная синхронизация локально — создать `.env.local` (не попадёт в git):

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...
```

Прод-сборка локально: `bun run build && bun run start`.
Проверить схему БД повторно: SQL из `scripts/supabase-schema.sql`
безопасно запускать повторно (idempotent).
